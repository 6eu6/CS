## 2. Architecture (inside `index.html`)

### Libraries

Loaded from a CDN with a fallback: cdnjs, then jsdelivr or unpkg.

- **Skulpt 1.2.0**: Python in the browser.
- **CodeMirror 5.65.16**: the editor, with the python mode, a custom csv mode and the show-hint addon.

### Key globals

| Global | Role |
|---|---|
| `LESSONS` | Built from `<article class="lesson" data-id data-week data-title [data-needs]>` |
| `R` | Coded exercises: `R[id] = {title, lvl, task, spec, code, stdin, files, tests:[T(inp, exp, label)], sol, stages:[{title, task, spec, tests, sol}], extra:c=>msg\|null}` |
| `PARS`, `BLANKS`, `BUGS`, `PRED`, `Q` | Data for the interactive widgets |
| `prelude(files, stdin)` | Python injected before user code. It provides a virtual file system (`_VFS`, `_dump()`), an `input()` that echoes typed values between U+2063 markers, and a stable `sorted` patch. |
| `runPython(code, files, stdin)` | Runs the code; `lastLines` compares the last N output lines with prompts and echoes removed. Tests can set `file:` (check a written file) and `after:` (code appended to the run). |
| `REQ`, `lockOf`, `lessonDone`, `weekDone` | Gating. See below. |
| `prog` | Progress object `{lessons, ex, ck, rev, focus, stage, drafts}`, saved under localStorage key `c50-prog`. `saveProg()` saves it and queues a sync. |
| `SYNC`, `mergeProg` | Account sync. Merging is a union, so it never loses progress. |
| `HINTS`, `LESSON_CONCEPTS`, `WIDGET_LESSON` | Generated by `tools/hints.py` |
| `LECTURES`, `LECT_MAP` | The lecture card per lesson: YouTube id, notes sections, `t` (start second, currently `null`) |
| `SAMPLE`, `askTutor` | Level-3 hint, the AI tutor |

### Gating rules

- Within a week, lessons unlock in order.
- Week N needs week N−1 done, **or** its `-test` placement lesson passed.
- Project parts need their week (`data-needs`) and unlock in order.
- Quizzes pass at 80%. Prediction drills pass at 80% on the first reveal.

### Hints

| Level | What the learner gets |
|---|---|
| 1 | The tools needed, each linked to the lesson that taught it |
| 2 | An outline generated from the solution's AST, with `___` blanks |
| 3 | The AI tutor. It never gives a full solution, uses only taught concepts, and replies in the learner's language. |

### Skulpt limitations (avoid in exercises, or note them in the lesson)

- Float repr can differ from CPython.
- Not supported: `{x=}` in f-strings, `removeprefix`, `match`, and the `.3e` format.

The scripts contain hard-coded scratchpad paths, so **update the `SP=` paths** before running them.

| Feature | On Vercel today | What it needs |
|---|---|---|

| Progress | ✅ Saved per browser (localStorage) | Nothing |
| **Embedded YouTube player** | ✅ Works (the page is top-level, so "Play here" appears) | Fill `LECT_MAP[*].t` with start seconds |

| **AI tutor (hint 3)** | ❌ Shows the fallback message | It used `window.claude.use('sample')`. **Replace it with a Vercel serverless function** that calls the Anthropic API (below). |

### 4.1 Sync: Firebase Auth + Firestore (recommended, free Spark plan)

The current sync code already uses a Firestore-shaped API:

- `db.collection(path).doc('progress')`
- `.set(...)`
- `.onSnapshot(snap => snap.exists, snap.data(), snap.hasPendingWrites)`

Using the **Firebase compat SDK** means almost no logic changes:

1. Create a Firebase project. Enable **Auth** (Google and email link) and **Firestore**.
2. Load `firebase-app-compat`, `firebase-auth-compat` and `firebase-firestore-compat` from a CDN.
3. In the sync block, swap the `window.claude` part for:
   ```js
   const user = await signInFlow();                        // a small sign-in button in the header
   SYNC.ref = firebase.firestore().collection('progress').doc(user.uid);
   ```
   Keep `mergeProg`, `pushProg` and `onSnapshot` exactly as they are.
4. Firestore security rules:
   ```
   match /progress/{uid} { allow read, write: if request.auth != null && request.auth.uid == uid; }
   ```
5. Keep localStorage as the offline cache, as it works now.

Supabase also works, but it needs a small adapter, because its API shape is different.

### 4.2 AI tutor: `/api/tutor` serverless function

1. Create `api/tutor.js`, a Vercel Node function.
   - It receives `{prompt}` and calls the **Anthropic Messages API** with streaming.
   - Use a small, cheap model, and keep the key in the `ANTHROPIC_API_KEY` env var. **Never put the key in the browser.**
2. Protect your bill:
   - Require sign-in: verify the Firebase ID token in the function.
   - Rate-limit per user, e.g. 30 questions a day, using Upstash Redis or Vercel KV.
   - Cap `max_tokens` at around 300.
3. In the page, set `SAMPLE` to an adapter with the same signature:
   ```js
   SAMPLE = async (prompt, {onText}) => { /* fetch('/api/tutor'), read the stream, call onText({text}) */ return {text} }
   ```
   The tutor rules already live in the prompt built by `askTutor`; keep them.

Cost note: the owner pays for API usage, so the limits above matter once the site is public.

### 4.3 Real Python with Pyodide (later, recommended)

- Pyodide is real CPython in WebAssembly. It fixes every Skulpt difference: float repr, `match`, `{x=}`, `removeprefix` and the standard library.
- `input()`: the runner already supplies stdin up front for tests. Use `pyodide.setStdin({stdin: () => nextLine()})` from that buffer, which needs **no** SharedArrayBuffer.
- Do **not** add COOP/COEP headers. They are only needed for SharedArrayBuffer, and they would break YouTube embeds and CDN loads.
- Load it in a Web Worker so a `while True` loop can't freeze the page. Add a "Stop" button that terminates the worker.
- After switching, delete the Skulpt notes and re-run `cpycheck.py`. Outputs should now match CPython exactly.

## 5. Content roadmap (agreed with the owner)

Work **week by week with high precision**: Week 0 (full rebuild to the new standard), then 1, 2, 3, and on to 9.

### Per-lesson template

1. **Learning objectives**: "After this lesson you can…" (3 points), checked again at the end.
2. **Lecture card**: the exact part of the video, and the notes link.
3. **📖 Official reference card**: 1–3 deep links to *only this lesson's* part of docs.python.org (Tutorial, Library Reference, Glossary), plus a small "reading task".
   - Licensing: docs code examples are 0BSD (free to copy); prose is under the PSF License (quote briefly with attribution, or paraphrase).
4. **Concept cycle**, for every concept:
   1. A real scenario first, as the hook.
   2. A symbol-by-symbol explanation, including why each name was chosen.
   3. The anatomy explorer.
   4. Worked examples (several variations).
   5. Predict the output.
   6. Guided practice (Parsons and fill in the blanks).
   7. Independent coding with tests.
   8. A scenario application.
5. **Common misconceptions** box.
6. **Scenario lab**: 4 domains × 3 exercises. Default domains: data, automation, apps/services, games/simulation (the owner may swap games for finance).
7. **Code-reading** and **debugging** exercises, with real tracebacks.
8. Short **Arabic summary** at the end, if the owner confirms it. The content itself stays English.

### Per-week targets

- 60+ coded exercises, 25+ interactive widgets, 40+ predictions.
- A project, plus the next **Pocket Ledger** part.
- A cheat sheet, mixed review that brings back earlier weeks, and a placement test.

### New skill lesson

"How to read Python documentation", at the end of Week 0. It covers:

- Signature notation: `[optional]`, `*`, `/`, default values.
- `help()` and `dir()`.
- Tutorial pages versus reference pages.
- Practice: predict what an unseen function does from its signature.

### Later ideas, prioritised

- An English–Arabic glossary.
- "Explain it back", graded by the tutor.
- A strengths and weaknesses dashboard.
