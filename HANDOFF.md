## 2. Architecture

### Libraries
Self-hosted in `vendor/` (no CDN needed; CDNs remain only as a fallback): **Skulpt 1.2.0** (Python in the browser), **CodeMirror 5.65.16**, and the fonts.

### Registries (`js/core/registry.js`)
Every data file fills these with `Object.assign(R, {...})`:
`R` coded exercises `{title, lvl, task, spec, code, stdin, files, tests:[T(inp, exp, label)], sol, stages, extra}` · `Q` quizzes · `STEP` steppers · `ANAT` anatomy · `PRED` predictions · `PARS` Parsons · `BLANKS` fill-ins · `BUGS` bug hunts.

### Other globals
`LESSONS` (built from the lesson articles, in manifest order) · `prog` (progress `{lessons, ex, ck, rev, focus, stage, drafts}` in localStorage key `c50-prog`) · `REQ`, `lockOf`, `lessonDone`, `weekDone` (gating, `js/progress/gating.js`) · `prelude`/`runPython` (engine) · `HINTS`, `WIDGET_LESSON` (generated) · `LECTURES`, `LECT_MAP` (lecture cards).

### Gating rules
- Within a week, lessons unlock in order; tests are exempt.
- Week N needs week N-1 done, **or** its `-test` lesson passed (placement test).
- Project parts need their week (`data-needs`) and unlock in order.
- Quizzes pass at 80%. Prediction drills pass at 80% on the first reveal.

### Hints (two levels, never a solution)
1. The tools you need, linked to the lessons that taught them.
2. An outline of one solution with `___` blanks, generated from the solution's AST by `tools/hints.py`.

There is intentionally no AI tutor.

### Skulpt limitations (avoid in exercises, or note them in the lesson)
- Float repr can differ from CPython.
- Not supported: `{x=}` in f-strings, `removeprefix`, `match`, and the `.3e` format.

## 3. Tools

| Command | Purpose |
|---|---|
| `bash tools/qa/check.sh` | **Run before every commit.** dump → CPython check → concept audit → smoke test |
| `node tools/qa/dump.js <dir>` | exports exercise data, test jobs and a structural fingerprint |
| `python3 tools/qa/cpycheck.py <dir>/jobs.json` | runs all reference solutions in real CPython |
| `python3 tools/audit.py <dir>/data.json tools/allow.json` | concept audit. `TAUGHT` maps each concept to the lesson that teaches it: add new concepts there as lessons are added |
| `python3 tools/hints.py <dir>/data.json content/hints.js tools/` | regenerates `content/hints.js` after exercises change |

Needs `node` with `playwright` and `python3`.

## 4. Deploying (Vercel)

Import the repo, framework preset **Other**, empty build command. Static files only; `vercel.json` sets security headers and long caching for `/vendor`. There is no backend. Progress lives in the browser; Export/Import moves it between devices.

Possible later upgrade: **Pyodide** (real CPython in WebAssembly, run in a Web Worker with a Stop button) to remove every Skulpt difference. Do not add COOP/COEP headers; they would break YouTube embeds.

## 5. Content roadmap (agreed with the owner)

Work **week by week with high precision**: Week 0 (full rebuild to the new standard), then 1, 2, 3, and on to 9.

### Per-lesson template

1. **Learning objectives**: "After this lesson you can…" (3 points), checked again at the end.
2. **Lecture card**: the exact part of the video, and the notes link.
3. **📖 Official reference card**: 1–3 deep links to *only this lesson's* part of docs.python.org (Tutorial, Library Reference, Glossary), plus a small "reading task".
   - Licensing: docs code examples are 0BSD (free to copy); prose is under the PSF License (quote briefly with attribution, or paraphrase).
4. **Concept cycle**, for every concept:
   1. A real scenario first, as the hook.
   2. A symbol-by-symbol explanation, including why each name was chosen.
   3. The anatomy explorer.
   4. Worked examples (several variations).
   5. Predict the output.
   6. Guided practice (Parsons and fill in the blanks).
   7. Independent coding with tests.
   8. A scenario application.
5. **Common misconceptions** box.
6. **Scenario lab**: 4 domains × 3 exercises. Default domains: data, automation, apps/services, games/simulation (the owner may swap games for finance).
7. **Code-reading** and **debugging** exercises, with real tracebacks.
8. Short **Arabic summary** at the end, if the owner confirms it. The content itself stays English.

### Per-week targets

- 60+ coded exercises, 25+ interactive widgets, 40+ predictions.
- A project, plus the next **Pocket Ledger** part.
- A cheat sheet, mixed review that brings back earlier weeks, and a placement test.

### New skill lesson

"How to read Python documentation", at the end of Week 0. It covers:

- Signature notation: `[optional]`, `*`, `/`, default values.
- `help()` and `dir()`.
- Tutorial pages versus reference pages.
- Practice: predict what an unseen function does from its signature.

### Later ideas, prioritised

- An English–Arabic glossary.
- "Explain it back" (the learner writes the explanation; compare it with a model answer, no AI).
- A strengths and weaknesses dashboard.

### Open decisions

Ask the owner if they are not already answered:

1. Scenario domains: keep the 4, or swap games for finance?
2. An Arabic summary per lesson: yes or no?
3. An independent review pass per week: a fresh agent tests each week as a new learner. Spawn agents only with the owner's consent.
