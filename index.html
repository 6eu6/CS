Week 0 · Lesson 1

print(): your first function, fully understood

25 minPlayground · 4 exercises

print("hello, world") looks trivial. It already contains four of the most important ideas in programming: functions, calling, arguments and strings.

Every character of print("hello, world")

print
The name of a function. A function is a named action someone already wrote. Python comes with about 70 built-in functions; print is the one that shows text in the terminal.
(
Brackets right after a function name mean call it: "run this action now". Without brackets, print is just the name of the tool, not the use of it.
"
Starts a string: a piece of text. The quote marks tell Python "this is data, not code". Without them, Python would think hello is the name of something.
hello, world
The text itself. Note the comma here is inside the quotes, so it's just a character of the text.
"
Ends the string. It must match the opening quote: "..." or '...', never mixed.
)
Ends the call. Every ( needs its ).

The value you put inside the brackets is an argument: the input you hand to the function. print's job is to take its arguments and display them.

Why quotes matter

print(hello) without quotes gives NameError: name 'hello' is not defined. Python looked for a variable called hello. Quotes are how you say "the literal text hello".

Several arguments at once

print("hello,", "Sara")          # hello, Sara
print("Total:", 42, "items")     # Total: 42 items

Commas between arguments (outside the quotes) separate them. print puts a space between each argument automatically and a line break at the end. Both of those are adjustable.

sep and end: the hidden parameters

print has extra settings with default values. You change them by name, using name=value inside the brackets. These are called keyword arguments.

sep=" "
What goes between arguments. Default: one space.
end="\n"
What goes after everything. Default: \n, a new line.
print("2026", "10", "25", sep="-")     # 2026-10-25
print("a", "b", "c", sep="")           # abc
print("Loading", end="...")
print("done")                          # Loading...done   (same line!)
print() playgroundInteractive

    

    
The output box shows ⏎ where a line break would be, and · for each space, so you can see invisible characters.

  


  
Escape sequences: typing the untypeable

  
Inside a string, a backslash \ means "the next character is special". Two characters in the code become one in the text.

Often simpler: use the other kind of quote outside. 'She said "hi"' needs no backslashes. "It's fine" neither.


  
Comments: notes for humans


# Ask the user for their name
name = input("What's your name? ")   # input returns a str

  
Everything after # on a line is ignored by Python. Use comments to explain why, not to repeat what the code obviously does. CS50 also suggests writing your plan as comments first ("pseudocode"), then filling in code under each one.


  
Bugs: your first one

A syntax error means Python can't even understand the shape of the code, so nothing runs. The fix is always on that line or the one just above it: a missing bracket, quote or colon.


  

  

  

  

  







  
Week 0 · Lesson 2

  
Variables, return values and input()

  
30 minStep-through tracer · 4 exercises

  
Programs get interesting when they react to the user. That needs two things: a way to ask (input) and a place to keep the answer (a variable).


  
Return values: functions that hand something back

  
print does something (shows text). Other functions give back a value you can use. That value is called the return value.


input("What's your name? ")

  
input shows the prompt, waits for the user to type and press Enter, then returns what they typed as a string. If you don't store it anywhere, it's lost immediately.


  
Variables: storing a value under a name


name = input("What's your name? ")
print("hello,", name)

  

    
name
A variable: a name you chose. It will refer to the value on the right.

    
=
The assignment operator. Read it as "gets" or "now refers to". It works right to left: first Python runs input(...) and waits for the user, then stores the result in name.

    
input(...)
Runs first. Its return value becomes the value of name.

  

  
= is not "equals"
In maths, x = x + 1 is impossible. In Python it's normal: "take the current x, add 1, store it back in x". Comparing two values uses ==, which you'll use in Week 1.


  


  
Why print("hello, name") doesn't work


name = "Sara"
print("hello, name")      # hello, name    ← the word "name", not the variable
print("hello,", name)     # hello, Sara    ← the variable's value

  
Inside quotes, name is just four letters. Outside quotes, it's the variable. You can join text and variables three ways:


print("hello,", name)          # 1. separate arguments (print adds a space)
print("hello, " + name)        # 2. + joins strings (you add the space yourself)
print(f"hello, {name}")        # 3. f-string: the modern, preferred way


  
Naming variables well

  
    
    
  • Letters, digits and underscores only; can't start with a digit; no spaces.
    • 
    
  • Lower case with underscores: first_name, total_price (called snake_case).
    • 
    
  • Describe the content: age beats a; price_with_vat beats p2.
    • 
    
  • Case matters: Name and name are different variables.
    • 
    
  • Don't reuse built-in names: input = "x" breaks input() for the rest of the program.
    • 
  


  
Reassigning and reusing


name = input("Name: ")      # "  sara "
name = name.strip()          # "sara"     same variable, new value
name = name.title()          # "Sara"
print(f"hello, {name}")

  
A variable can be given a new value any time. The old value is forgotten. This "clean it step by step" pattern is very common with user input.


  
input() always returns a string
Even if the user types 42, input returns the text "42". To do maths you must convert it with int() or float(). Lesson 4 is all about this. It's the most common Week 0 bug.

Strings and their methods: cleaning up what users type

  
35 minMethod lab · 6 exercises

  
Users type messy things: extra spaces, random capitals, the wrong separator. String methods are the tools for tidying that up before you use it.


  
What a method is


name = "  sARA  "
name.strip()

  
A method is a function that belongs to a value. You call it with a dot: value.method(). The dot means "use the strip ability that belongs to this string". Strings come with dozens of methods.

  
Strings never change; methods return new ones
name.strip() does not change name. It returns a cleaned copy. If you don't store it, the copy is lost:


name = "  sara  "
name.strip()          # cleaned copy made... and thrown away
print(name)           # "  sara  "  still messy!
name = name.strip()   # store the copy back
print(name)           # "sara"

  
Strings are immutable: once made, they can't be edited, only replaced. This is the #1 string bug for beginners.

Chaining methods


name = input("Name: ").strip().title()

  
Read it left to right: input(...) returns a string → .strip() is called on that and returns a new string → .title() is called on that. Each dot works on the result of everything to its left.

  
Order matters
"  sara".capitalize().strip() gives "sara" (capitalize hit the space). "  sara".strip().capitalize() gives "Sara". Strip first, then change case.


  
split() and unpacking


full = "Ada Lovelace"
first, last = full.split(" ")     # first = "Ada", last = "Lovelace"
print(f"hello, {first}")

  
split(" ") returns a list of pieces. Writing two names on the left with a comma unpacks the two pieces into two variables. If the text has three pieces, you'd get ValueError: too many values to unpack, so this only works when you know how many pieces there are.


  
Joining and repeating


"tea" + "pot"         # "teapot"     + joins strings
"ha" * 3              # "hahaha"     * repeats
"-" * 20              # "--------------------"  handy for dividers
"Age: " + 30          # TypeError: can only concatenate str (not "int") to str


  
Picking characters: indexing and slicing


word = "python"
word[0]      # "p"      the first character is position 0
word[-1]     # "n"      negative counts from the end
word[0:3]    # "pyt"    from 0 up to (not including) 3
word[:2]     # "py"     from the start
word[2:]     # "thon"   to the end

  
Positions start at 0. Slices include the start and exclude the end. You'll use this for initials, codes and file extensions.


  
Scenario: a sign-up form
A user types their email as "  Sara.Ali@Example.COM ". Before saving it you'd do email = email.strip().lower(), because emails are case-insensitive and stray spaces cause "user not found" bugs later. Websites you use every day do exactly this.


  

  

  

  

  

  

  







  
Week 0 · Lesson 4

  
Numbers: int, float, operators and formatting

  
40 minOperator lab · 6 exercises

  
Text is for people; numbers are for calculating. The trick is knowing which kind of number you have, which operator you need, and how to show the result nicely.


  
Two kinds of numbers

  

    
int
Integer: a whole number, no decimal point. 3, -12, 2026. Use for counting things: people, items, seconds, years.

    
float
Floating-point number: has a decimal point. 3.5, -0.25, 2.0. Use for measuring: prices, distances, temperatures.

  

  
type(x) tells you what you have: type(3) is <class 'int'>, type(3.0) is <class 'float'>, type("3") is <class 'str'>.


  
The operators

  

    
Operator labInteractive

    

      
      
    

    

  

  
// and % are a pair
17 // 5 is 3 (how many whole 5s fit) and 17 % 5 is 2 (what's left over). Together they split anything into "whole units and remainder": 135 minutes → 135 // 60 = 2 hours and 135 % 60 = 15 minutes. You'll use this pair constantly.

  
Order of operations is the same as in maths: ** first, then * / // %, then + -. Use brackets when in doubt: (a + b) / 2, not a + b / 2.


  
Converting: int(), float(), str()


x = input("x: ")      # user types 2  → x is "2" (a str)
y = input("y: ")      # user types 3  → y is "3"
print(x + y)          # 23   ← + joined two strings!

x = int(input("x: "))   # convert straight away
y = int(input("y: "))
print(x + y)            # 5

  

    
int("42")
→ 42. int("4.5") fails with ValueError, and so does int("forty").

    
float("4.5")
→ 4.5. Also accepts "42" → 42.0.

    
int(4.9)
→ 4. Converting a float to int cuts off the decimals; it doesn't round.

    
str(42)
→ "42". Needed when joining with +: "Age: " + str(age).

  

  
Nesting: int(input(...))
Python runs the innermost brackets first: input returns a string, then int converts it. Doing it in one line means the variable is a number from the start, so you can't forget to convert later.


  
Rounding and formatting


price = 19.98765
round(price)          # 20        nearest whole number
round(price, 2)       # 19.99     2 decimal places
f"{price:.2f}"        # '19.99'   a STRING with exactly 2 decimals
f"{3:.2f}"            # '3.00'    keeps trailing zeros (round(3, 2) gives 3)
f"{1234567:,}"        # '1,234,567'  thousands separators
f"£{1234.5:,.2f}"     # '£1,234.50'  both together: money

Floats are not exact


print(0.1 + 0.2)      # 0.30000000000000004

  
Computers store floats in binary, and some decimals (like 0.1) can't be stored exactly, the way 1/3 can't be written exactly in decimal. It's not a bug in your code. Format your output with :.2f and it disappears. For real money systems, professionals use whole pennies (ints) or Python's decimal module.


  
Scenario: splitting a restaurant bill
£87.40 between 3 friends: 87.40 / 3 is 29.1333... Show f"£{87.40 / 3:.2f}" → "£29.13". Every banking, shopping and fitness app does this kind of convert-calculate-format sequence.


  

  

  

  

  

  

  







  
Week 0 · Lesson 5

  
def: writing your own functions

  
45 minScope tracer · 6 exercises

  
So far you've called functions other people wrote. Now you write your own. This is the most important idea of the week, and every later week depends on it.


  
The smallest function


def hello():
    print("hello")

hello()
hello()

  

    
def
"Define": I'm creating a new function. Python stores the instructions but doesn't run them yet.

    
hello
The name you chose. Same naming rules as variables. Use a verb: it does something.

    
()
The parameter list. Empty here: this function needs no input.

    
:
"The body comes next."

    
4 spaces
Indentation marks the body: the lines that belong to the function. When the indentation stops, the function ends.

    
hello()
A call. Now the body actually runs. Two calls, two hellos.

  


  
Parameters: giving a function input


def hello(to):
    print("hello,", to)

hello("Sara")       # hello, Sara
hello("Omar")       # hello, Omar

  
to is a parameter: a variable that gets its value from the call. When you write hello("Sara"), Python does to = "Sara" just before the body runs. The value you pass, "Sara", is the argument.

  
Why "to"? Could it be anything?
Yes. def hello(person) or def hello(x) work identically, as long as the body uses the same name. Programmers pick a name that makes the body read like English: print("hello,", to). Parameter names are for the human reader.


  
Default values


def hello(to="world"):
    print("hello,", to)

hello()            # hello, world   ← no argument, so the default is used
hello("Sara")      # hello, Sara

  
to="world" means "if no argument is given, use "world"". That's exactly how print's sep=" " and end="\n" work.


  
return: giving a value back


def square(n):
    return n * n

x = square(4)          # x is 16
print(square(3) + 1)   # 10

  
return does two things: it hands a value back to the caller, and it ends the function immediately. Any line after return in the same block never runs.

  

    
print inside a function
Shows a value to the person. The caller gets None back and can't use it.

    
return inside a function
Gives the value to the code that called it, so that code can store it, calculate with it, or print it.

  


def bad_square(n):
    print(n * n)       # shows 16...

x = bad_square(4)      # ...but x is None
print(x + 1)           # TypeError: unsupported operand type(s) for +: 'NoneType' and 'int'

  
Rule of thumb
Functions that calculate should return. Let main decide what to print. That way the same function works in a terminal program, a website, or a test.


  
main(): organising a program


def main():
    name = input("Name: ")
    hello(name)

def hello(to):
    print("hello,", to)

main()

  
CS50P uses this shape for every program. main holds the big picture; helper functions do the details. Notice hello is defined below main and it still works. That's because main() is only called on the last line, by which time Python has read every def.

  
Later in the course you'll see this instead of the plain main():


if __name__ == "__main__":
    main()

  
It means "run main only if this file was run directly, not imported by another file". It matters in Week 5 (unit tests). For now, either works.


  
Scope: where a variable lives

  
A variable created inside a function exists only inside that function, and only while it's running. That's called its scope.


def main():
    name = input("Name: ")
    hello()

def hello():
    print("hello,", name)    # NameError: name 'name' is not defined

main()

  
name belongs to main. hello can't see it. The fix is to pass it in as an argument: hello(name) and def hello(to). Passing values in and returning values out is how functions talk to each other.

  

  
Why does Python work this way?
If every function could see and change every variable, a change in one place could silently break another. Scope keeps each function self-contained: you can understand it by reading just that function, its parameters and its return.

Anatomy of if / elif / else

  

  
Exactly one branch runs

  
Python checks the conditions top to bottom and runs the first branch whose condition is true. Then it skips the rest, even if later conditions are also true. If none match, else runs (if there is one).

if score >= 70:

Users type nonsense: negative ages, "maybe" to a yes/no question, letters where you wanted a number. The loop in this lesson is how every real program handles that: keep asking until you get something usable.


  
break: leave the loop now


for n in range(1, 100):
    if n * n > 50:
        break          # jump straight out of the loop
    print(n)           # 1 2 3 4 5 6 7

break ends the innermost loop immediately. Python continues with the first line after the loop. The rest of the iterations never happen.

for n in range(1, 8):
    if n % 3 == 0:
        continue       # skip the rest of THIS iteration
    print(n)           # 1 2 4 5 7   (3 and 6 skipped)

  
continue doesn't leave the loop. It jumps back to the top for the next item. Use it to skip items you don't care about without nesting the rest of the body inside an if.

You can't test the answer before you've asked. With while True you ask first, then test, then break/return when it's good. The alternative needs the input() call written twice (once before the loop, once inside), which is easy to get out of sync.

Dictionaries: looking things up by name

  
45 minAnatomy · trace · 8 predictions · 6 exercises

  
A list finds things by position: "the 3rd student". A dictionary finds things by a name you choose: "Sara's house", "the price of tea". It's the data structure behind phone books, menus, settings and the word counter.


  
Anatomy

  


  
Everything you can do with a dict


menu = {"tea": 1.80, "coffee": 2.40}

menu["tea"]             # 1.8       look up a value by its key
menu["cake"] = 3.10     # add a new key-value pair
menu["tea"] = 1.95      # replace the value for an existing key
"coffee" in menu        # True      is this KEY present? (doesn't search values)
menu["juice"]           # KeyError: 'juice'
menu.get("juice")       # None      no error
menu.get("juice", 0)    # 0         your own default
del menu["coffee"]      # remove a pair
len(menu)               # 2         number of pairs

  
Why are dictionaries so fast?
Finding a value in a list means checking items one by one. A dict jumps straight to the key, no matter whether it has 10 entries or 10 million. That's why "look up by name" problems should almost always use a dict.

  
Rules for keys
Keys must be unique (assigning the same key twice replaces the value) and must be unchangeable values: strings and numbers are fine, lists are not. Values can be anything, including lists and other dicts.


  
Looping over a dictionary


houses = {"Sara": "Red", "Omar": "Blue", "Lina": "Red"}

for name in houses:                 # loops over the KEYS
    print(name, houses[name])

for name, house in houses.items():  # keys and values together (clearer)
    print(f"{name} is in {house}")

for house in houses.values():       # just the values
    print(house)

  
Since Python 3.7, dictionaries remember the order in which keys were added, so loops go in that order.


  
The tally pattern (counting with a dict)

  


counts[w] = counts.get(w, 0) + 1    # the same tally in one line

The seven loop patterns

  
40 minPattern identification drill · 6 exercises

  
Experienced programmers don't invent loops from scratch. They recognise which pattern a problem needs and adapt it. Almost every loop you'll write in CS50P is one of these seven, or two of them combined.


  
1. Sum (accumulate)

    total += price

count = 0
for t in temps:
    if t > 25:
        count += 1        # add 1, not t

  
Use for: "how many…" questions. The difference from sum: you add 1, not the value.

best = scores[0]          # start with a REAL item, not 0
for s in scores:
    if s > best:
        best = s

  
Use for: highest, lowest, longest, earliest. Start with the first item, because starting at 0 breaks when all values are negative. (max() exists, but you need this pattern when you also want e.g. who had the best score.)

passed = []
for s in scores:
    if s >= 50:
        passed.append(s)

  
Use for: "all the ones that…". Builds a new list; the original is untouched.

clean = []
for name in names:

split() and join(): text to pieces and back

The question it answers
split: "How do I break this line of text into its parts?" join: "How do I glue a list of strings into one line?" They are exact opposites.

  
Anatomy of join (the one everyone finds odd)

  

  
Why is it ", ".join(list) and not list.join(", ")?
Because join belongs to strings, and it works on any iterable of strings: lists, tuples, generators, dict keys. Putting it on the separator means one method serves them all. Read it as: "use ", " to join these".

  
split in detail


"a  b\tc\n".split()        # ['a', 'b', 'c']        no argument: any whitespace, runs merged, ends ignored
"a,,b".split(",")           # ['a', '', 'b']         with a separator: every comma counts, empties kept
"k=v=w".split("=", 1)       # ['k', 'v=w']           maxsplit: only split once
"".split(",")               # ['']                   one empty piece, not an empty list!

  
join in detail


", ".join(["tea", "jam"])           # 'tea, jam'
"".join(["a", "b", "c"])            # 'abc'
"\n".join(["line 1", "line 2"])     # two lines in one string
", ".join([1, 2])                   # TypeError: expected str instance, int found
", ".join(str(n) for n in [1, 2])   # '1, 2'

  
Building strings: join beats +=
s += piece in a loop is fine for small jobs, but each += creates a whole new string. Collecting pieces in a list and joining once at the end is the professional habit, and it's much faster for large output.

repr(): seeing exactly what's inside a value

  
45 min5 scenarios · 8 predictions · 6 exercises

  
print() shows you a value the way a user should see it. repr() shows it the way a programmer needs to see it: with quotes, hidden spaces, tabs and line breaks made visible. Half of all "it looks right but doesn't work" bugs are found in seconds with repr.


  
The question it answers
"What exactly is inside this variable?" Not what it looks like when printed. What it really is.


  
The name

  
repr is short for representation. It returns a string that represents the value as Python source code would write it. For most simple values, if you typed repr's output into Python, you'd get the same value back.


  
The problem it solves, in one example

  
A user typed their name into a form. You compare it and it fails. You print it to check:


name = "Sara "             # imagine this came from input(), with a stray space
print(name)                # Sara       ← looks perfect
print(name == "Sara")      # False      ← but why?!
print(repr(name))          # 'Sara '    ← there it is: a space before the closing quote

  
print can't show you a trailing space: it's invisible. repr wraps the value in quotes, so you can see exactly where the text starts and ends.

Why containers already use repr
When you print a list, Python shows each item with repr, not str. That's why print(["Sara "]) shows ['Sara '] with the space visible. Python's designers chose this because a list of strings printed with str would be ambiguous: [a, b] could be two names or two strings.

print(f"[{name}]")        # [Sara ]   3. the poor man's version: brackets around it

  
In real Python 3.8 or newer there's a fourth, beloved by professionals: print(f"{name=}") prints name='Sara ', the variable's name and its repr. It's the fastest debug print there is. (The in-browser engine on this site doesn't support = in f-strings, so try that one in your Codespace.)

sorted(), key= and lambda: ordering by any rule

  
45 minSort lab · 5 scenarios · 5 exercises

  
The question it answers
"Put these in order, but by my rule: by price, by length, by surname, by score then by name…"


  
Anatomy

  


  
How key= really works

  
Python calls your key function once per item, gets back a "sort value" for each, sorts by those values, and returns the original items in that order. The key never changes the items; it only decides their order.


words = ["banana", "fig", "apple"]
sorted(words)               # ['apple', 'banana', 'fig']        alphabetical
sorted(words, key=len)      # ['fig', 'apple', 'banana']        len("fig")=3, len("apple")=5, len("banana")=6
sorted(words, key=len, reverse=True)   # ['banana', 'apple', 'fig']

  

    
Sort labInteractive

    
Data: people = [("Sara", "Ali", 31), ("omar", "Khan", 25), ("Lina", "Ali", 25), ("zaid", "Noor", 40)]

    

      

    

    

  


  
lambda: a function in one line


lambda p: p[2]
# is exactly the same as:
def get_age(p):
    return p[2]

  
lambda makes a small function without a name. Before the colon: the parameter(s). After it: the value to return (no return keyword). Use it when the function is tiny and used once, which is almost always the case with key=.


  
Sorting by several things: tuples

  
Tuples are compared item by item: first items first; only if equal, the second items, and so on. So key=lambda p: (p[1], p[0]) means "by surname, then by first name". To sort one part descending and another ascending, negate the number: (-score, name).

Python's sort is stable: items with equal keys keep their original order. Professionals use this deliberately: sort by name first, then by department, and people within each department stay alphabetical.


  
Real-work scenarios

  
Scenario 1: A leaderboard with tie-breaks

    print(name, s)
# Omar 95 / Lina 88 / Sara 88   ← ties broken alphabetically

  
Scenario 2: Case-insensitive sorting of names

  
sorted(["bob", "Alice", "carl"]) gives ['Alice', 'bob', 'carl'], but only by luck: capitals come before all lower-case letters. sorted(["bob", "alice", "Carl"]) puts Carl first. Fix: key=str.lower. You can pass a method itself as the key, without calling it.

  
Scenario 3: The most common words (the word counter!)

Now every piece is clear: pairs, sorted by the count (x[1]), biggest first, the first 10.

  
Scenario 4: Dates as text

  
Dates written 2026-11-02 (year-month-day, the ISO format) sort correctly as plain text. Dates written 02/11/2026 don't. That's one reason professionals store dates in ISO format. To sort the other style, build a key: key=lambda d: (d[6:], d[3:5], d[:2]).

"Which one is the biggest/smallest by my rule, and what do they add up to?"


max([4, 9, 2])                    # 9

sales = {"tea": 140, "cake": 95, "coffee": 210}

Looping over a dict gives its keys. key=sales.get means "judge each key by its value". The result is the key with the biggest value: the answer to "which product sold most?" in one line. Note sales.get without brackets: we pass the method itself for max to call.

staff = [{"name": "Sara", "sales": 31}, {"name": "Omar", "sales": 44}]

30 min4 scenarios · 6 predictions · 4 exercises

  
The question it answers
"I have related data in separate lists. How do I go through them together, item by item?"

  
The name

  
Like a zip on a jacket: two separate sides joined tooth by tooth.

  
Anatomy

  


names = ["Sara", "Omar", "Lina"]
scores = [88, 72, 95]
list(zip(names, scores))       # [('Sara', 88), ('Omar', 72), ('Lina', 95)]

zip stops at the shortest list
zip([1, 2, 3], ["a", "b"]) gives only 2 pairs. The 3 is silently dropped. When lists should be the same length, check len(a) == len(b) first, or you can lose data without any error.

any() and all(): rules over a whole collection

  
30 min3 scenarios · 4 exercises

  
The question it answers
any: "does at least one item pass?" all: "does every item pass?"


any([False, True, False])        # True
all([True, True, False])         # False
any(ch.isdigit() for ch in "abc3")     # True   ← a generator: checks each character
all(score >= 50 for score in [70, 55, 90])   # True

  
The part inside the brackets, ch.isdigit() for ch in "abc3", is a generator expression: like a list comprehension without the square brackets. It makes one True/False per item, lazily.

  
They stop early
any stops at the first True; all stops at the first False. On a million items where the first one fails, all() checks one item. This is called short-circuiting, the same as and/or.

  
The empty-list surprise
all([]) is True ("no item failed") and any([]) is False. If "no data" should count as failure, check the length too: len(x) > 0 and all(...).

The dict toolkit: get, setdefault, items, pop, update

  
40 min4 scenarios · 5 exercises

  
The question it answers
"How do I look up, count, group and merge data by key without KeyErrors and without messy if/else?"

  

    
MethodWhat it doesReach for it when

    
d.get(k, default)Value or default, never an errorReading a key that may be missing; tallies

    
d.setdefault(k, default)Returns d[k]; if missing, sets it to default firstGrouping into lists: d.setdefault(k, []).append(x)

setdefault, step by step

  


by_dept = {}
for name, dept in [("Sara", "IT"), ("Omar", "HR"), ("Lina", "IT")]:
    by_dept.setdefault(dept, []).append(name)
print(by_dept)      # {'IT': ['Sara', 'Lina'], 'HR': ['Omar']}

  
Without setdefault you need four lines: if dept not in by_dept: by_dept[dept] = [] then append. Both are correct. setdefault is the idiom you'll see in professional code; the if-version is clearer while learning. Know both.

  
get(k, []).append(x) is a bug
d.get(k, []) returns a new empty list that is not stored in the dict. Appending to it does nothing to d. For "append to a list in a dict", use setdefault.
