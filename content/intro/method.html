The study method: how to come out of CS50P genuinely skilled

10 min readDo this every week

Most people who "finish" an online course can't write a program from scratch a month later. The difference isn't talent; it's how they practised. Here's a weekly loop that works.

The weekly loop

StepWhat you doWhy it works
1. WatchWatch the CS50P lecture with your Codespace open. Pause and type every example yourself. Don't just watch.Typing forces you to notice every symbol. Watching feels like learning but mostly isn't.
2. UnderstandRead this week's companion lessons. Use the "Try it" boxes to break the examples on purpose.You find the gaps the lecture went past too quickly.
3. DrillDo the practice lab, warm-up to challenge. Aim for green ticks without opening the solution.Many small reps build the reflex of "I know which tool this needs".
4. ProveDo CS50's problem sets alone, with only the CS50 Duck (cs50.ai) for hints.Struggling a bit is exactly how memory forms. If someone gives you the answer, the learning is lost.
5. ReviewTwo or three days later, take the week test again and redo one lab exercise from a blank editor.Spaced review is what turns "I understood it" into "I can do it".

Your study session, exactly

Use the focus timer in the top bar. It follows the Pomodoro method: 25 minutes of focus, a 5-minute break, and a longer 15-minute break after every 4 sessions. Short, timed sessions stop you drifting and make starting easy ("just one session").

Why this works

Learning research consistently finds that three things beat re-reading: retrieval (answering from memory: the quizzes and predictions), spacing (coming back after days: the daily review) and active practice (writing code, not watching it). Timed sessions with breaks keep your attention fresh enough to do those well.

How progress works

  • A lesson is complete only when every exercise, drill and quiz in it is passed. The bar at the top of each lesson shows what's left.
  • The next lesson stays locked until then. Toolbox deep dives are never locked: use them whenever you need them.
  • Each week's final test works as a placement test: pass it and the next week unlocks, even if you skipped lessons you already know.
  • Quizzes need 80%. Prediction drills need 80% on the first reveal. Projects unlock step by step.

Rules that make the difference

  • Predict before you run. Before pressing Run, say what you expect the output to be. When you're wrong, that's the most valuable moment of the session.
  • Read errors to the last line. Python almost always tells you what's wrong and where. Learn to read it instead of guessing.
  • Twenty minutes, then ask. Stuck for 20 minutes? Explain the problem to the CS50 Duck, or to a rubber duck on your desk. Saying it out loud often solves it.
  • Never copy code you can't explain. If you can't explain a line, you don't own it yet.
  • Small steps. Write two lines, run, check. Then two more. Beginners write 30 lines and then face 5 errors at once.

Academic honesty, in plain words

CS50 treats using AI tools other than its own (ChatGPT, Claude, Copilot and so on) to suggest or write problem-set answers as academically dishonest. CS50's own Duck is allowed. So:

Fine

  • Using this companion to understand concepts
  • Doing the companion's own exercises
  • Asking me to explain an error message or a concept in general
  • Using the CS50 Duck for problem-set hints

Not fine

  • Pasting a problem set's spec into any AI and using its code
  • Copying someone's solution from GitHub
  • Asking for "just a hint" until the hints add up to the answer

Your setup

CS50P uses its own online VS Code at cs50.dev (it runs in GitHub Codespaces, which you're already using). Your terminal commands are the same everywhere:

code hello.py        # create/open a file in the editor
python hello.py      # run it
ls                   # list files here
cd folder            # move into a folder
cd ..                # go up one folder
check50 cs50/problems/2022/python/...   # CS50's official checker (the slug is in each problem's page)
submit50 ...         # submit (also on each problem's page)

The "Check" buttons on this site work like a mini check50: they run your code several times with different inputs and show which tests passed.
