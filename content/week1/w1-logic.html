The "or" trap

if answer == "y" or "yes": is always true, because "yes" on its own is a non-empty string, which counts as true. Each side of or must be a complete condition.

Precedence: not first, then and, then or. So a or b and c means a or (b and c). Add brackets for the reader.

Why short-circuiting matters

if text != "" and text[0] == "A": is safe: when text is empty, text[0] is never evaluated. Swap the sides and an empty string crashes with IndexError. Put the "guard" test first.

Truthiness

In an if, Python accepts any value. These count as False ("falsy"): False, None, 0, 0.0, "" (and empty collections you'll meet in Week 2). Everything else is "truthy", including "0" and " ".

name = input("Name: ").strip()
if not name:                  # empty string → falsy
    print("Please enter a name")
