Loops inside loops: grids and patterns

35 minPattern builder · trace · 6 predictions · 5 exercises

Put a loop inside another and the inner one runs completely for every single iteration of the outer one. That's how you handle anything two-dimensional: rows and columns, tables, seats in a cinema, pixels in an image.

Watch it run

How many times does the inner body run?

outer iterations × inner iterations. 2 rows × 3 columns = 6 #. With 1,000 × 1,000 it's a million, which is why nested loops over big data can be slow.

The rows-and-columns way of thinking

For any grid or pattern, ask two questions: how many rows? (the outer loop) and what goes in row number r? (the inner loop, which may depend on r).

Helper functions make nested loops readable


def main():
    print_square(3)

def print_square(size):
    for _ in range(size):        # each row
        print_row(size)

def print_row(width):
    print("#" * width)           # the inner "loop" is hidden in * repetition

main()

  
CS50P does exactly this: break the problem into "print a square" → "print a row". Each function does one simple thing. When a nested loop gets confusing, pull the inner loop out into a function.


  
break only leaves one loop


for r in range(3):
    for c in range(3):
        if c == 1:
            break           # leaves the INNER loop only
        print(r, c)
# prints  0 0  /  1 0  /  2 0   — the outer loop carries on
