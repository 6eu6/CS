break, continue, and asking until the answer is valid

40 minAnatomy · trace · 7 predictions · 5 exercises

Users type nonsense: negative ages, "maybe" to a yes/no question, letters where you wanted a number. The loop in this lesson is how every real program handles that: keep asking until you get something usable.

break: leave the loop now

for n in range(1, 100):
    if n * n > 50:
        break          # jump straight out of the loop
    print(n)           # 1 2 3 4 5 6 7
print("done")

break ends the innermost loop immediately. Python continues with the first line after the loop. The rest of the iterations never happen.

continue: skip to the next iteration

for n in range(1, 8):
    if n % 3 == 0:
        continue       # skip the rest of THIS iteration
    print(n)           # 1 2 4 5 7   (3 and 6 skipped)

continue doesn't leave the loop. It jumps back to the top for the next item. Use it to skip items you don't care about without nesting the rest of the body inside an if.

while True: the validation loop

Why while True and not a normal condition?

You can't test the answer before you've asked. With while True you ask first, then test, then break/return when it's good. The alternative needs the input() call written twice (once before the loop, once inside), which is easy to get out of sync.

return inside a loop

In a function, return does even more than break: it leaves the loop and the whole function, handing back a value. That's why get_age above can return straight from inside while True. Wrapping validation in a function means main stays clean: age = get_age() and you know it's valid.

Counting attempts

attempts = 0
while attempts < 3:
    guess = input("Password: ")
    if guess == "open sesame":
        print("Welcome")
        break
    attempts += 1
    print(f"Wrong. {3 - attempts} tries left")

Two ways to stop: the condition becomes false (3 failures) or break (success). After the loop you often need to know which one happened; check the variable: if attempts == 3: print("Locked").

Sentinel values: "stop when they type done"

total = 0
while True:
    item = input("Price (or done): ")
    if item == "done":
        break
    total += float(item)
print(f"Total: £{total:.2f}")

A sentinel is a special value that means "stop". Here it's the word done. You don't know how many prices the user will enter; the sentinel lets them decide.

What if they type letters where you need a number?

float("abc") crashes with ValueError. In Week 3 (Exceptions) you'll learn try/except to catch that inside the validation loop. For this week, exercises give you inputs that are numbers when a number is expected.
