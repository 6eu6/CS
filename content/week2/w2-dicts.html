Dictionaries: looking things up by name

45 minAnatomy · trace · 8 predictions · 6 exercises

A list finds things by position: "the 3rd student". A dictionary finds things by a name you choose: "Sara's house", "the price of tea". It's the data structure behind phone books, menus, settings and the word counter.

Anatomy

Everything you can do with a dict

menu = {"tea": 1.80, "coffee": 2.40}

menu["tea"]             # 1.8       look up a value by its key
menu["cake"] = 3.10     # add a new key-value pair
menu["tea"] = 1.95      # replace the value for an existing key
"coffee" in menu        # True      is this KEY present? (doesn't search values)
menu["juice"]           # KeyError: 'juice'
menu.get("juice")       # None      no error
menu.get("juice", 0)    # 0         your own default
del menu["coffee"]      # remove a pair
len(menu)               # 2         number of pairs
Why are dictionaries so fast?

Finding a value in a list means checking items one by one. A dict jumps straight to the key, no matter whether it has 10 entries or 10 million. That's why "look up by name" problems should almost always use a dict.

Rules for keys

Keys must be unique (assigning the same key twice replaces the value) and must be unchangeable values: strings and numbers are fine, lists are not. Values can be anything, including lists and other dicts.

Looping over a dictionary

houses = {"Sara": "Red", "Omar": "Blue", "Lina": "Red"}

for name in houses:                 # loops over the KEYS
    print(name, houses[name])

for name, house in houses.items():  # keys and values together (clearer)
    print(f"{name} is in {house}")

for house in houses.values():       # just the values
    print(house)

Since Python 3.7, dictionaries remember the order in which keys were added, so loops go in that order.

The tally pattern (counting with a dict)

counts[w] = counts.get(w, 0) + 1    # the same tally in one line

Lists of dictionaries: records

Real data usually looks like rows in a spreadsheet: several fields per thing. In Python that's a list of dicts, one dict per row:

students = [
    {"name": "Sara", "house": "Red",  "score": 88},
    {"name": "Omar", "house": "Blue", "score": 72},
    {"name": "Lina", "house": "Red",  "score": 95},
]
for s in students:
    print(s["name"], "scored", s["score"])

top = students[0]
for s in students:
    if s["score"] > top["score"]:
        top = s
print("Top:", top["name"])          # Top: Lina

Notice the double lookup s["score"]: s is one dict from the list, and ["score"] picks a field from it. This shape is exactly what you'll get when you read a CSV file in Week 6, and what web APIs send in Week 4.

Choosing: list or dict?

Question you'll ask the dataUse
"What's the 3rd one?" / "In what order?"list
"What is X's value?" (phone, price, score)dict
"How many of each?"dict (tally)
"All the rows, each with several fields"list of dicts
"Which items belong to group X?"dict of lists
