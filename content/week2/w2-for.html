A for loop says "do this for each item". You don't manage a counter or a condition; Python hands you the items one at a time and stops when they run out.

Anatomy

What range() really produces

range creates a sequence of whole numbers. It has three forms:

CallNumbersRead it as
range(5)0, 1, 2, 3, 45 numbers starting at 0
range(1, 6)1, 2, 3, 4, 5from 1 up to, not including, 6
range(0, 10, 2)0, 2, 4, 6, 8start 0, stop before 10, step 2
range(5, 0, -1)5, 4, 3, 2, 1counting down: negative step
range(3, 3)(nothing)start equals stop: zero iterations
Why does the stop number get left out?

So that range(n) gives exactly n numbers, and so that range(len(items)) gives exactly the valid positions of a list (which also start at 0). It feels odd for a week, then it becomes natural. Same rule as slicing: word[0:3] excludes position 3.

The pattern in that trace, start a total at 0, add to it inside the loop, use it after the loop, is called an accumulator. You'll use it constantly.


  
for over anything you can walk through


for letter in "cat":        # a string: one character at a time
    print(letter)           # c, a, t

for name in ["Sara", "Omar", "Lina"]:   # a list: one item at a time
    print("hello,", name)

  
Anything you can loop over is called an iterable: strings, lists, ranges, dictionaries, files. The loop variable (letter, name) is a name you choose; pick the singular of what you're looping through.


  
The underscore: "I don't need the number"


for _ in range(3):
    print("meow")

  
_ is a perfectly valid variable name. By convention it means "there's a value here, but I won't use it". It tells the reader: this loop is only about repeating, not about the numbers.


  
The loop variable after the loop


for i in range(3):
    pass          # pass = "do nothing", a placeholder body
print(i)          # 2   the last value it was given


  
for vs while side by side

  


i = 0
while i < 3:
    print(i)
    i += 1


for i in range(3):
    print(i)

  

  
Identical output. The for version can't forget the increment and can't loop forever, which is why it's preferred whenever you know the sequence in advance.


  
Printing on one line inside a loop


for i in range(5):
    print(i, end=" ")      # 0 1 2 3 4   all on one line
print()                    # finish the line (prints just "\n")

  
Remember end from Week 0? Inside loops it's essential for building a line piece by piece. The empty print() afterwards moves to a new line.
