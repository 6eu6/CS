The question it answers

"How do I look up, count, group and merge data by key without KeyErrors and without messy if/else?"

setdefault, step by step

by_dept = {}
for name, dept in [("Sara", "IT"), ("Omar", "HR"), ("Lina", "IT")]:
    by_dept.setdefault(dept, []).append(name)
print(by_dept)      # {'IT': ['Sara', 'Lina'], 'HR': ['Omar']}

Without setdefault you need four lines: if dept not in by_dept: by_dept[dept] = [] then append. Both are correct. setdefault is the idiom you'll see in professional code; the if-version is clearer while learning. Know both.

get(k, []).append(x) is a bug

d.get(k, []) returns a new empty list that is not stored in the dict. Appending to it does nothing to d. For "append to a list in a dict", use setdefault.

Real-work scenarios

Scenario 1: Settings with defaults

defaults = {"currency": "GBP", "decimals": 2, "theme": "light"}
user = {"theme": "dark"}
settings = defaults.copy()
settings.update(user)          # user choices win
print(settings)    # {'currency': 'GBP', 'decimals': 2, 'theme': 'dark'}

This "defaults, then overrides" pattern is how almost every app handles configuration.

Scenario 2: Inventory movements

stock = {"tea": 10}
for item, change in [("tea", -3), ("jam", 5), ("tea", 4)]:
    stock[item] = stock.get(item, 0) + change
print(stock)       # {'tea': 11, 'jam': 5}

Scenario 3: Translating codes

status_names = {"P": "Pending", "S": "Shipped", "D": "Delivered"}
for code in ["S", "X", "D"]:
    print(status_names.get(code, f"Unknown ({code!r})"))

A dict used as a lookup table replaces long if/elif chains. Adding a status means adding one entry, not a new branch.

Scenario 4: Inverting a dict

house = {"Sara": "Red", "Omar": "Blue", "Lina": "Red"}
members = {}
for person, h in house.items():
    members.setdefault(h, []).append(person)
# {'Red': ['Sara', 'Lina'], 'Blue': ['Omar']}
